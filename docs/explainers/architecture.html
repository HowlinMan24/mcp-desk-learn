How MCP Desk works

You ask a question. Claude answers word by word, and it can ask to use tools. Each tool lives in a separate program called an MCP server. You approve each tool call.

Why the loop matters

Claude never runs anything itself. It only asks. Your code runs the tool and sends the result back in a new request. That loop is what makes it an agent, and it is the same in Node and in Go.

stateDiagram-v2
  [*] --> CallClaude
  CallClaude --> Finished: no tool requested
  CallClaude --> WaitForApproval: tool requested
  WaitForApproval --> RunTool: Allow
  WaitForApproval --> CallClaude: Decline, Claude is told
  RunTool --> CallClaude: result added to history
  Finished --> [*]

The database

erDiagram
  CONVERSATIONS ||--o{ MESSAGES : has
  CONVERSATIONS {
    uuid id PK
    text title
    timestamptz updated_at
  }
  MESSAGES {
    uuid conversation_id PK
    int seq PK
    role role
    jsonb content
  }

Messages are only ever added. The content column keeps the blocks exactly as the API sent them, because Claude needs its history back unchanged.

Check yourself

Who actually runs a tool: Claude or your code?

Your code. Claude only asks for it, and your code decides whether to run it.

Why does a tool call need two requests to Claude?

The first ends with Claude asking for the tool. The second sends the result, so Claude can write the final answer.
